## 使用示例

### 基础分析

```python
from moss.core.performance_engine import PerformanceEngine, PerformanceConfig

# 初始化引擎
config = PerformanceConfig(
    enable_incremental=True,
    enable_parallel=True,
    max_workers=8
)
engine = PerformanceEngine("/path/to/codebase", config)

# 分析代码库
report = await engine.analyze_codebase(
    analysis_type='full',
    use_incremental=True,
    use_parallel=True
)

print(f"分析完成: {report.duration:.2f}s")
print(f"缓存命中: {report.cache_hits}/{report.file_count}")
print(f"加速比: {report.parallel_speedup:.1f}x")
```

### 高性能重构

```python
# 使用增量分析执行重构
result = await engine.refactor_with_performance(
    symbol_name="MyClass",
    source_module="moss.core.old_module",
    target_module="moss.core.new_module",
    dry_run=False
)
```

### 性能基准测试

```python
# 运行完整基准测试
results = await engine.run_performance_benchmark()

stats = engine.get_performance_stats()
print(f"缓存命中率: {stats['cache_hit_rate']:.1f}%")
```

## 技术亮点

### 1. 智能缓存策略
- **LRU 淘汰**：内存缓存使用 OrderedDict 实现 O(1) 访问
- **TTL 支持**：磁盘缓存支持按条目设置过期时间
- **自动提升**：热点数据自动从 L2→L1, L3→L2→L1 提升
- **校验和验证**：SHA256 检测文件内容变化

### 2. 并行优化
- **进程池复用**：避免频繁创建/销毁进程开销
- **任务分块**：批量提交任务减少调度开销
- **依赖排序**：使用 NetworkX 拓扑排序处理依赖关系
- **动态调度**：根据文件数量自动调整工作进程数

### 3. 混合策略
- **自适应选择**：根据文件数量和分析类型自动选择最优策略
- **缓存优先**：优先检查缓存，避免重复计算
- **增量回退**：缓存失效时自动回退到增量分析

## 已知限制

### 1. 并行分析
- **小文件开销**：文件数 < 10 时，串行可能更快
- **进程启动成本**：首次分析有 ~0.5s 启动开销
- **内存占用**：每个进程占用独立内存空间

### 2. 缓存
- **首次分析**：无缓存时仍需全量分析
- **磁盘空间**：L2/L3 缓存可能占用较大磁盘空间
- **并发写入**：多进程同时写入 L3 缓存可能有竞争

### 3. 依赖分析
- **动态导入**：无法追踪动态导入 (importlib)
- **C 扩展**：无法分析 C 扩展模块的依赖
- **循环依赖**：复杂循环依赖可能影响增量准确性
