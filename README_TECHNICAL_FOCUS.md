# MOSS 项目 - 技术焦点声明

**日期**: 2026-04-22  
**决策**: 暂不考虑论文发表  
**焦点**: 深度技术验证

---

## 决策背景

经过统筹评估，我们决定**暂不追求论文发表**，而是专注于：

1. **技术严谨性**: 充分的实验验证 (N=10, N=45, 100 代)
2. **代码质量**: 完善的 LLM 集成和文档
3. **可复现性**: 开源代码和详细实验记录
4. **社区价值**: 提供可用的 AGI 研究框架

---

## 为什么暂不考虑论文？

### 优势

✅ **更充分的验证**
- 无需赶 NeurIPS/ICML 截止
- 可以运行 N=10+ 重复实验
- 可以进行长期稳定性测试 (100 代)

✅ **更高质量代码**
- 有时间完善 LLM 集成
- 添加全面的测试和文档
- 优化用户体验

✅ **更开放的协作**
- 开源优先策略
- 吸引社区贡献
- 建立技术影响力

### 风险缓解

⚠️ **优先权问题**
- 通过 GitHub Release 记录时间戳
- 发布技术报告 (arXiv 预印本可选)
- 保持技术领先优势

⚠️ **学术认可**
- 后续仍可基于技术成果撰写论文
- 代码引用和 GitHub Stars 作为影响力指标
- 开源社区认可度

## 与学术论文的区别

| 维度 | 技术焦点 | 论文焦点 |
|------|----------|----------|
| **目标** | 构建可用系统 | 发表新颖发现 |
| **验证** | 充分重复 (N=10+) | 最小可发表 (N=3-5) |
| **代码** | 生产质量 | 研究原型 |
| **文档** | 用户友好 | 学术规范 |
| **时间** | 按需 (质量优先) | 截止驱动 |
| **认可** | GitHub Stars, 引用 |  citations, h-index |

## 未来论文可能性

虽然当前不考虑论文，但技术验证完成后：

### 可选路径

1. **arXiv 技术报告** (低门槛)
   - 快速发布，建立优先权
   - 无需同行评审
   - 可引用 DOI

2. **开源软件论文** (JOSS)
   - Journal of Open Source Software
   - 专注于软件质量
   - 快速评审 (~4 周)

3. **AI 会议/期刊** (可选)
   - 基于完整技术成果
   - 无时间压力
   - 选择最合适的 venue

### 决策标准

是否撰写论文将基于：
- 技术成果的创新性
- 社区反馈和需求
- 团队兴趣和资源
